Tap Relay — Webhook integration reference

Overview

Tap Relay sends an HTTPS POST to your endpoint every time a Flic 2 button is pressed. Your server receives structured JSON with the event details and responds with a status code. This page documents everything you need to build a webhook receiver.

Webhook Payload

Each button press sends the following JSON body:

{
  "client_id":    "site-alpha-01",
  "auth_token":   "tok_abc123...",
  "button_mac":   "AA:BB:CC:DD:EE:FF",
  "click_type":   "single",
  "pressed_at":   "2026-05-26T14:30:00Z",
  "delivered_at": "2026-05-26T14:30:01Z",
  "queued":       false,
  "age_seconds":  1.2
}

Field Reference

FieldTypeDescription
client_id string Identifier assigned during provisioning. Use this to route events to the correct handler.
auth_token string Bearer token for authenticating the request. Validate this on your server.
button_mac string Bluetooth MAC address of the Flic 2 button.
click_type string One of: single, double, or hold.
pressed_at ISO 8601 When the button was physically pressed (device clock).
delivered_at ISO 8601 When the webhook was dispatched from the device.
queued boolean true if the event was queued due to no connectivity at press time.
age_seconds number Seconds between press and delivery. Useful for detecting stale events.

HTTP Details

Request

Method: POST

Content-Type: application/json

Authorization: Bearer {auth_token}

Expected Response

Return HTTP 200 to acknowledge receipt.

Any 2xx status is treated as success. Non-2xx responses or timeouts will show as failed delivery in the app's event log.

Minimal Receiver Examples

Node.js (Express)

const express = require('express');
const app = express();
app.use(express.json());

app.post('/webhook/taprelay', (req, res) => {
  const { auth_token, client_id, click_type } = req.body;

  // Validate token
  if (auth_token !== process.env.EXPECTED_TOKEN) {
    return res.status(401).json({ error: 'unauthorized' });
  }

  console.log(`[${client_id}] ${click_type} press`);
  res.status(200).json({ received: true });
});

app.listen(3000);

Python (Flask)

from flask import Flask, request, jsonify
import os

app = Flask(__name__)

@app.route('/webhook/taprelay', methods=['POST'])
def handle_press():
    data = request.json
    if data['auth_token'] != os.environ['EXPECTED_TOKEN']:
        return jsonify(error='unauthorized'), 401

    print(f"[{data['client_id']}] {data['click_type']} press")
    return jsonify(received=True), 200

QR Provisioning Format

If you're generating QR codes to provision devices, the payload must be a JSON object with these fields:

{
  "flic_mac":     "AA:BB:CC:DD:EE:FF",   // target button
  "webhook_url":  "https://api.example.com/webhook/taprelay",
  "auth_token":   "tok_abc123...",
  "client_id":    "site-alpha-01",
  "sig":          "hmac-sha256-hex...",  // HMAC signature
  "exp":          1748300000              // expiry (Unix timestamp)
}
FieldNotes
flic_macrequiredColon-separated MAC of the target Flic 2
webhook_urlrequiredMust be HTTPS
auth_tokenrequiredBearer token for webhook auth
client_idrequiredUnique identifier for this deployment
sigrequiredHMAC-SHA256 of the payload fields
expoptionalQR expiration; app rejects if expired

Best Practices

  • Validate the auth token on every request. Treat it like a bearer token.
  • Check age_seconds to discard stale events if timeliness matters (e.g., reject events older than 60 seconds).
  • Use client_id to route events when managing multiple buttons or sites.
  • Respond quickly. The app waits for your response. A fast 200 ensures the event log updates promptly.
  • Idempotency: If you need it, use pressed_at + button_mac as a natural deduplication key.
  • HTTPS only. The app enforces TLS. Self-signed certificates are not supported.

Rate Limits & Behavior

  • Events fire in real time — there is no batching
  • The Flic button hardware debounces presses, so duplicate events are rare
  • If connectivity is lost, events queue on-device and deliver when connectivity returns (marked "queued": true)

Location Accuracy

Important

The lat, lng, and location_accuracy fields reflect the device's last known location, not a live GPS fix. When the app is in the background, iOS does not continuously update location. If the user has moved significantly since the app was last in the foreground, the coordinates may be stale by minutes or miles.

For safety-critical use cases (lone worker alerts, distress signals, check-ins where current position matters): do not rely solely on the webhook location. Use Apple Find My or a dedicated location-tracking service to obtain the user's real-time position. The webhook location is best treated as an approximate reference, not a ground truth.
